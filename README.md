# Agent 价值与真实体验评测模板

[下载 Excel 模板](outputs/01a0e736/AI研发Agent四工具试点评测模板.xlsx)

围绕同一个需求，并排填写 **Claude Code、Codex、Trae、CodeArts** 的实际使用反馈。一张工作表，每个工具都有“记录 / 主要感受说明”和“1～5 分”两列。

模板参考 [Issue #1 收集的开发者反馈](https://github.com/coolplayagent/compare-agentharness/issues/1)，采用 **19 项核心流程＋9 项进阶选填**。先按开发过程回顾，再总结价值；只评价实际体验过的项目。反馈中的个别产品经历用于设计问题，不作为工具能力或优劣的预设结论。

## 自然的填写顺序

先填写受访者与任务背景，再按下表顺序填写。每项用 1～3 句话说明发生了什么、影响如何、人工做了什么，再评分。黄色区域是填写区。

| 阶段 | 内容与顺序 |
| --- | --- |
| 共同背景 | 姓名或昵称、岗位（选填）；需求描述、技术栈、业务场景、项目起点、完成标准、代码仓库地址。多个仓库 URL 可换行填写。 |
| 开始使用（1 项） | 先记录模型、版本与入口、环境、硬件限制、熟悉程度和本次配置，再评价**上手与环境接入**。 |
| 理解需求与制定方案（5 项） | **意图理解 → Codebase 与技术栈理解 → 项目指令与约束遵从 → 联网搜索与方案咨询 → 任务规划与调整**。 |
| 执行任务与处理问题（6 项） | **工具 / Skill / MCP 选择与调用 → 沟通确认与过程可控性 → 错误识别与自动纠正 → 长任务连续执行与中断恢复 → Context 窗口管理与压缩 → Session 查看、切换与恢复**。随后记录人工介入次数。 |
| 检查交付结果（4 项） | 先记录任务完成情况，再评价**需求实现准确性、代码可用性与维护质量、Spec 与交付说明质量、主动验证与测试质量**。 |
| 回顾效率与投入（2 项） | 先记录执行总耗时、速度观察、费用及额度影响，再评价**响应与迭代效率、资源占用与运行流畅性**。 |
| 进阶能力，按需选填（9 项） | **跨会话与项目记忆、轨迹反馈与持续改进、多 Agent 与跨 Session 编排、并发稳定性、应用集成与互操作、外部编排与调度、通过自然语言配置 Agent 自身、Computer Use、Browser Use**。并发规模放在并发稳定性前。 |
| 总结价值与心得（1 项） | 最后评价**最有价值的特性**，写出具体事件和实际帮助。整体心得、继续使用意愿、改进建议不评分。 |

共 28 项评价、112 个评分格。进阶区只填写本次使用或长期观察过的能力，可以整区跳过，直接写最后的价值与心得。核心流程中不适用或未体验的项目也可以留空。

## 背景与事实记录

**实际模型名称**填写界面显示的模型全称及版本。多个模型注明用途；自动选择填写“Auto”，实际模型不可见时注明“未显示”。模板不预填各工具所用模型。

**开发与执行环境**区分主机系统（Windows / Linux / macOS / 其他）与实际执行位置（本机 / WSL / 容器 / 远程主机 / 云环境）。例如 Windows 主机、WSL Linux 执行，应同时记录。硬件和资源数据注明来自哪个环境。

| 记录项 | 参考方式 |
| --- | --- |
| 熟悉程度 | 首次使用、偶尔使用、经常使用。 |
| 人工介入次数 | 0 次、1～2 次、3～5 次、6 次及以上；指启动后补充指令、纠正方向或人工接管。 |
| 任务完成情况 | 全部完成、大部分完成、约一半、少部分完成、未完成；补充剩余工作和人工补做内容。 |
| 执行总耗时 | 准确时长或 ≤15 分钟、>15～30 分钟、>30～60 分钟、>1～2 小时、>2 小时。 |
| 速度观察（选填） | 首字响应、仓库索引 / 启动、排队和追问完成速度，填写秒 / 分钟或“无明显等待、有等待、明显拖慢任务”。 |
| 费用、Token 与额度影响（选填） | 本次实际费用及币种；可得时补充 Token 用量，说明限流和额度影响。未知不按零处理。 |
| 并发规模 | 实际数量或 1 路、2 路、3～5 路、6 路及以上；注明 Session、子 Agent、独立进程或云任务。 |

参考下拉选项允许自行补充实际值。执行总耗时从下发需求计至本轮交付或停止，包含纠错、重试和人工介入，排除无关暂停。未完成任务也记录已耗时；如观察到首次可运行代码的时间，可在说明中补充。首字响应从提交输入计至首次开始输出，各段耗时不要求相加。耗时、费用、Token 和采纳情况都不自动换算成分数。

## Issue #1 反馈如何落入模板

原有 22 项能力全部保留并重新归类，新增 6 项独立评价：**项目指令遵从、工具选择调用、沟通确认、应用集成互操作、外部编排调度、自然语言配置 Agent 自身**。

| 反馈主题 | 填写位置与观察重点 |
| --- | --- |
| 工具形态、网络接入、代理与配置 | 版本与入口、开发环境、上手体验；说明连接和配置排错是否方便。 |
| 项目规范及提示文件的遵从 | 项目指令与约束遵从；观察 AGENTS.md 等约束在长任务、压缩后是否仍被遵循。 |
| 项目上下文、复杂改动和特定技术栈 | Codebase 与技术栈理解、需求实现准确性；描述存量代码理解、跨文件改动及本项目技术栈的实际表现。 |
| 方案咨询、搜索与任务规划 | 联网搜索与方案咨询、任务规划与调整；观察资料来源、版本适配、API 准确性及计划更新。 |
| 工具、Skill、MCP 的准确选用 | 工具选择与调用；关注选用、传参、无效调用与失败后重复尝试。 |
| 提问、审批及等待期间的推进 | 沟通确认与过程可控性；说明确认理由是否清楚，能否继续处理不依赖回答的工作，以及暂停后的恢复。 |
| 中断、服务异常与长任务 | 长任务连续执行与中断恢复；区分网络、模型 / 服务、工具、审批 / 人工暂停或原因不明。长期可用性反馈注明观察时段，不按原因直接扣分。 |
| 跨会话记忆、项目经验和操作历史 | 跨会话与项目记忆；观察正确复用、遗忘以及过期信息的影响。 |
| 会话查看、切换和版本更新后的延续 | Session 查看、切换与恢复；观察任务状态和工作流能否保留。 |
| 多任务协作、会话通信与工作区隔离 | 多 Agent 与跨 Session 编排、并发规模及稳定性；描述分工、worktree 隔离、结果整合和跨任务干扰。 |
| 首轮结果、代码采纳及代码质量 | 代码可用性与维护质量；说明编译、运行或合入结果、bug / 漏洞、人工修改量和实际采纳情况。 |
| 主动生成测试与前端验证 | 主动验证与测试质量；观察测试能否运行、关键路径和边界覆盖、实际交互检查以及修复后的复验。 |
| GitHub、IM、通知、文件行号与链接 | 应用集成与互操作；观察任务处理、状态同步、结果定位和跳转是否顺畅。 |
| 通过自然语言安装、调整自身能力 | 通过自然语言配置 Agent 自身；记录 Skill、Agent、Hook、Scheduler 等配置的完成、生效反馈和修正体验。 |
| 外部系统调度 Agent | 外部编排与调度；记录任务发起、跟踪、结果回传、恢复与协作衔接。 |
| 首字、排队、大仓库启动、追问与总体耗时 | 速度观察、执行总耗时、响应与迭代效率；结合高峰限流和重复探索描述真实等待。 |
| 同等任务花费与 Token 使用 | 费用、Token 与额度影响，结合最终交付和整体心得理解，不要求专业统计或自动排名。 |

Context 项关注当前窗口压缩后信息是否保留，记忆项关注持久复用。自动纠错评价本次错误处理，持续改进需要后续任务减少同类错误，并注明自动发生还是人工整理经验后实现。一次重试成功不视为持续改进。

Computer Use、Browser Use 和联网搜索分别关注桌面操作、浏览器交互、资料查找与应用，不预设工具一定支持。资源项可填写真实卡顿感受，有数据时注明内存 MiB / GiB、CPU % 和观察环境；共享服务注明整体观测值。只体验单路时，并发稳定性评分留空。

## 评分与使用

| 分数 | 参考含义 |
| --- | --- |
| 1 很差 | 明显不满足需要，严重影响任务。 |
| 2 较差 | 帮助有限、问题频繁，需要较多干预。 |
| 3 一般 | 基本可用，仍有明显不足。 |
| 4 较好 | 表现良好，仅有少量问题。 |
| 5 很好 | 充分满足本次场景需要，表现稳定顺畅。 |

高分统一表示更好：上手越容易、资源影响越小，评分越高。最有价值的特性按实际帮助程度评分。未体验、不适用或无法判断时留空，在说明中写明原因；实际尝试失败可以评分。模板不设置需求号、总分、权重、排名或预填结论。

评分格只接受 1～5 的整数或空白。工具表头和评价项列已冻结，说明区自动换行，较长文字可调整行高。其他需求可复制工作表继续填写。

## 验证与打印

验证覆盖 28 项分类及顺序、原有能力保留、112 个评分格、20 个可自定义参考下拉框、空白填写区、冻结窗格和导出重开。使用临时数据核对指令遗漏、工具选错、等待确认、网络中断、主动测试、文件跳转、跨会话记忆、外部调度和高峰排队等反馈的填写位置；验证数据不写入正式模板。

打印设置为 A3 横向、单页宽度、纵向分页，并调整分区起页位置，每页重复工具表头。通过 LibreOffice Calc 进行原生校验与打印检查，未在 Microsoft Excel 客户端实测。
