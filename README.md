# Agent 价值与真实体验评测模板

[下载 Excel 模板](outputs/01a0e736/AI研发Agent四工具试点评测模板.xlsx)

这份模板供实际使用研发 Agent 的开发者记录体验：围绕同一个需求，并排填写 **Claude Code、Codex、Trae、CodeArts** 在理解、执行、交付和投入上的表现，帮助团队结合具体场景讨论工具的价值。

模板只有一张工作表，每个工具各有“记录 / 主要感受说明”和“1～5 分”两列。共 **21 项核心评价＋9 项进阶选填**。只填写实际体验过的工具与项目，无需为了填表尝试所有能力。

## 快速开始

1. **写清共同背景。** 填写需求、业务场景、技术栈、项目起点、仓库地址与完成标准。姓名和岗位选填；同一需求的共同背景只填一次。
2. **记录各工具的实际配置。** 填写模型、版本与入口、开发和执行环境、熟悉程度；有影响的硬件限制及扩展配置按需补充。
3. **按开发过程回顾。** 在黄色区域用 1～3 句话写清“发生了什么、对任务有什么影响、人工做了什么”，再对已体验的项目评分。记录项不评分。
4. **先完成核心总结。** 写出最有价值的特性、整体心得、继续使用意愿及改进建议。
5. **按需补充进阶能力。** 进阶区在总结之后，可以整区跳过。换一个需求时，复制工作表继续填写。

未体验的工具可以整列留空。已使用工具中的单项若不适用或无法判断，评分留空，在说明中注明原因。

## 按什么顺序填写

下表与 Excel 的分区和顺序一致。条目数量仅统计需要评分的评价项，不包含背景、事实记录和开放反馈。

| 分区 | 内容与顺序 |
| --- | --- |
| 受访者与任务背景 | 共同背景只填一次；先明确需求和场景，再写仓库地址与完成标准。 |
| 开始使用（2 项） | 先记录配置，再评价 **上手与环境接入 → 终端输出与环境兼容性**。 |
| 理解需求与制定方案（5 项） | **意图理解 → Codebase 与技术栈理解 → 项目指令与约束遵从 → 联网搜索与方案咨询 → 任务规划与调整**。 |
| 推进任务与过程交互（4 项） | **工具 / Skill / MCP 选择与调用 → 沟通确认与过程可控性 → 快捷操作与任务控制 → 错误识别与自动纠正**，随后记录人工介入次数。 |
| 上下文与会话连续性（3 项） | **长任务连续执行与中断恢复 → Context 窗口管理与压缩 → Session 历史查看、切换与恢复**，随后记录中断分类与恢复方式。 |
| 检查交付结果（4 项） | 先记录任务完成情况，再评价 **需求实现准确性 → 代码可用性与维护质量 → 主动验证与测试质量 → Spec 与交付说明质量**。 |
| 回顾效率与投入（2 项） | 先记录执行总耗时、速度观察、费用与额度影响，再评价 **响应与迭代效率 → 资源占用与运行流畅性**。 |
| 总结价值与心得（1 项） | 评价 **最有价值的特性**；整体心得、继续使用意愿与改进建议不评分。 |
| 进阶能力（9 项，选填） | 核心评价完成后，再按下表补充实际使用或长期观察过的能力。 |

进阶能力分为三组，按组阅读即可：

| 选填组 | 评价顺序 |
| --- | --- |
| 记忆与改进（2 项） | 跨会话与项目记忆 → 轨迹反馈与持续改进。 |
| 协作与调度（3 项） | 多 Agent 与跨 Session 编排 → 并发稳定性 → 外部编排与调度。**并发规模**紧邻并发稳定性之前记录；只体验单路时不评并发稳定性。 |
| 扩展与外部操作（4 项） | 应用集成与互操作 → 通过自然语言配置 Agent 自身 → Browser Use → Computer Use。 |

## 怎样记录事实和评分

### 背景与事实记录

**实际模型名称**填写界面显示的模型全称及版本。多个模型注明用途；自动选择填“Auto”，实际模型不可见时注明“未显示”。模板不预填各工具所用模型。

**开发与执行环境**区分主机系统和实际执行位置。例如 Windows 主机、WSL Linux 执行，应同时记录。补充实际终端 / Shell；编码信息已知或遇到乱码时选填。硬件、CPU 和内存数据注明来自主机、容器还是远程环境。

| 记录项 | 填写方式 |
| --- | --- |
| 项目起点 | 从零开发、修改已有项目；可补充其他实际情况。 |
| 工具熟悉程度 | 首次使用、偶尔使用、经常使用；可补充频率或经验。 |
| 人工介入次数 | 0 次、1～2 次、3～5 次、6 次及以上；指启动后补充指令、纠正方向或人工接管。 |
| 中断分类 | 网络、模型 / 服务、工具、审批 / 人工暂停或原因不明；同时写恢复方式。长期可用性反馈注明观察时段。 |
| 任务完成情况 | 全部、大部分、约一半、少部分、未完成；按完成标准判断，补充剩余工作及人工补做内容。 |
| 执行总耗时 | 准确时长或 ≤15 分钟、>15～30 分钟、>30～60 分钟、>1～2 小时、>2 小时。未完成任务也记录已耗时。 |
| 速度观察（选填） | 首字响应、仓库索引 / 启动、排队、追问完成速度；写秒 / 分钟，或“无明显等待、有等待、明显拖慢任务”。 |
| 费用、Token 与额度影响（选填） | 本次实际费用及币种；可得时补充 Token 用量，说明限流和额度影响。未知留空。 |
| 并发规模 | 实际数量或 1 路、2 路、3～5 路、6 路及以上；注明 Session、子 Agent、独立进程或云任务。 |

参考下拉选项允许自行补充实际值。仓库地址可换行填写多个 URL。

执行总耗时从下发需求计至本轮交付或停止，包含纠错、重试和人工介入，排除无关暂停。首字响应从提交输入计至首次开始输出，各段耗时不要求相加。首次可运行代码的时间可在说明中补充。耗时、费用、Token、采纳情况及中断原因都不自动换算分数。

### 评分口径

| 分数 | 参考含义 |
| --- | --- |
| 1 很差 | 明显不满足需要，严重影响任务。 |
| 2 较差 | 帮助有限、问题频繁，需要较多干预。 |
| 3 一般 | 基本可用，仍有明显不足。 |
| 4 较好 | 表现良好，仅有少量问题。 |
| 5 很好 | 充分满足本次场景需要，表现稳定顺畅。 |

高分统一表示更好：上手越容易、资源影响越小，评分越高。“最有价值的特性”按实际帮助程度评分。未体验、不适用或无法判断时留空；**实际尝试失败可以评分，未知不计零分**。

30 项评价对应四工具共 120 个评分格，设置为 1～5 的整数或空白。模板不设置需求号、总分、权重或排名，也不预填结论。阅读反馈时，应结合模型、环境、任务和具体经历理解分数。

### 相近条目如何区分

| 条目 | 主要观察什么 |
| --- | --- |
| 沟通确认与过程可控性 | 提问、审批是否必要且理由清楚；进展是否可见；等待回答时能否推进独立工作。 |
| 快捷操作与任务控制 | 追加指令、临时旁问、持续目标、回退、分叉、简化等操作是否易发现、易使用，以及操作后主任务能否正确衔接。 |
| 长任务连续执行与中断恢复 | 多步骤任务能否持续推进，中断后能否续接而不重复劳动。 |
| Context 窗口管理与压缩 | 当前窗口压缩后的目标、约束、决定和待办是否保留。 |
| Session 历史查看、切换与恢复 | 历史对话是否完整、加载是否顺畅，切换、重启或更新后能否找回并延续任务。 |
| 跨会话与项目记忆 | 项目约束、经验和历史操作能否跨会话正确复用，有无过期信息干扰。 |
| 错误识别与自动纠正／轨迹反馈与持续改进 | 前者看本次错误处理；后者需要后续任务减少同类错误，并注明自动发生还是人工整理经验后实现。一次重试成功不等于持续改进。 |
| 终端输出与环境兼容性／资源占用与运行流畅性 | 前者看输出、中文、路径和日志的可读性及环境适配；后者看 CPU、内存、资源释放和整体卡顿。 |

同一事件可以在相关项中引用，按各项实际影响分别判断。联网搜索评价资料查找与应用，Browser Use 评价网页交互，Computer Use 评价桌面操作，不预设工具一定支持。

资源项可以只写真实卡顿感受，无需专业监控。有数据时注明内存 MiB / GiB、CPU % 和观察环境；共享服务注明整体观测值，不强行归因于某个 Agent。

## 填写示例

以下为假设场景，用于演示记录方式，不代表任何工具的实际表现，也不预设分数。

| 假设经历 | 填写位置与示例说明 |
| --- | --- |
| 执行中临时询问一个问题 | 在“快捷操作与任务控制”写：“执行过程中追加一个旁问，回答后继续原任务，无需重新下发目标。”结合实际便利程度评分。 |
| 查看历史后需要重启 | 在“Session 历史查看、切换与恢复”写：“打开既往对话时卡顿，重启后能看到历史，但需要重新说明未完成事项，增加了人工补充。”中断分类写“原因不明，重启会话后恢复”。 |
| Windows 下命令输出乱码 | 先记录 Windows 主机、实际执行位置与终端 / Shell；在“终端输出与环境兼容性”写：“命令返回的中文日志乱码，无法辨认失败原因；人工重新查看日志后继续任务。”编码或根因不明时如实注明。 |

如果本轮任务未完成，在“任务完成情况”记录剩余工作，在“执行总耗时”填写已耗时；其他已体验项目仍可评价。如果只用过一个工具，只填写该工具对应列。

## 反馈依据与本次调整

模板以 [Issue #1 的开发者反馈](https://github.com/coolplayagent/compare-agentharness/issues/1) 为基础，并根据 [Issue #2](https://github.com/coolplayagent/compare-agentharness/issues/2) 继续调整。个别产品经历用于设计观察问题，不作为工具能力或优劣的预设结论。

原有 28 项评价全部保留，新增“快捷操作与任务控制”“终端输出与环境兼容性”。执行阶段拆分为过程交互与会话连续性；交付阶段先检查结果和测试，再看说明文档；核心总结提前到进阶区之前。

| Issue #2 反馈 | 模板中的对应调整 |
| --- | --- |
| 长程任务中的引导、旁问、目标与快捷命令体验有差异 | 新增“快捷操作与任务控制”，覆盖实际可用操作及操作后的主任务衔接。`steer`、`btw`、`/goal`、`/rewind`、`/fork`、`/simplify` 仅作为反馈中的示例，不要求同名命令，不按命令数量评分。 |
| 查看既往对话时丢失、卡顿，需要重启 | 强化 Session 项，明确历史完整性、加载、重启和恢复，并与窗口压缩及长任务推进区分。 |
| Windows 命令工具输出乱码 | 新增“终端输出与环境兼容性”；环境记录补充实际终端 / Shell，编码信息按需填写，不预设故障原因。 |

Issue #1 涉及的项目指令遵从、工具选择、等待确认、主动测试、应用互操作、跨会话记忆、外部调度、自然语言配置，以及耗时和费用等观察点继续保留。

## 使用与兼容性

工具表头和评价项、填写提示两列已冻结，说明区自动换行。较长反馈可以调整行高；填写新需求时可复制工作表。打印采用 A3 横向、单页宽度、纵向分页，每页重复工具表头。

已核对 30 项评价、120 个评分格及参考下拉校验，完成导出重开与全表渲染检查。空白模板在 LibreOffice Calc 下为 5 页 A3 横向，重存后校验规则和冻结设置保持一致。未在 Microsoft Excel 客户端实测；填写较长文本、调整行高后，建议重新检查分页。
