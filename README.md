# Agent 价值与真实体验评测模板

[下载 Excel 模板](outputs/01a0e736/AI研发Agent四工具试点评测模板.xlsx)

一张工作表，围绕同一个需求，并排填写 **Claude Code、Codex、Trae、CodeArts** 的实际使用反馈。每个工具都有“记录 / 主要感受说明”和“1～5 分”两列。黄色区域可填写，未体验项可以跳过。

## 填写方法

1. 填写共同背景：受访者姓名或昵称、岗位（选填），以及需求描述、技术栈、业务场景、项目起点和完成标准。
2. 按工具填写实际模型名称、工具版本与入口、开发和执行环境、硬件与资源限制、熟悉程度及相关配置。
3. 记录执行时长、人工介入次数、并发规模、任务完成情况。成本和额度影响选填。
4. 对实际体验过的项目，用 1～3 句话写出具体事件、影响和人工补救情况，再评分。
5. 在表尾写整体心得、是否愿意继续使用及改进建议。其他需求可以复制整张工作表继续填写。

## 模型、环境与参考范围

模型填写界面显示的**实际模型全称及版本**。使用多个模型时注明用途；自动选择填写“Auto”，能查到实际模型则补充，无法查到则注明“未显示”。模板不预设各工具所用模型。

开发环境分别说明主机系统（Windows / Linux / macOS / 其他）和实际执行位置（本机 / WSL / 容器 / 远程主机 / 云环境）。例如 Windows 主机、WSL Linux 执行，应同时记录。硬件与资源数据注明来自哪个环境。

| 记录项 | 参考范围 |
| --- | --- |
| 执行时长 | ≤15 分钟、>15～30 分钟、>30～60 分钟、>1～2 小时、>2 小时，也可填写准确时长。 |
| 人工介入次数 | 0 次、1～2 次、3～5 次、6 次及以上。指启动后补充指令、纠正方向或人工接管。 |
| 并发规模 | 1 路、2 路、3～5 路、6 路及以上，并注明 Session、子 Agent 或独立进程。 |
| 完成情况 | 全部完成、大部分完成、约一半、少部分完成、未完成；补充人工补做和剩余工作。 |
| 熟悉程度 | 首次使用、偶尔使用、经常使用。 |

参考选项提供下拉列表，也允许自行输入更准确的记录。时长包含本轮纠错、重试与人工介入，排除无关暂停；未完成任务也记录已耗时。参考区间不自动换算成评分。

## 22 项体验评价

| 分组 | 评价项 |
| --- | --- |
| 价值与交付质量（7 项） | 最有价值的特性、准确性、模型错误容错与自动纠错、长程任务连续性、Spec 文档质量、代码与运行质量、主动质量检查。 |
| Harness 使用体验（13 项） | 上手配置与扩展接入、Codebase 理解、记忆、Context 窗口管理与压缩、多 Agent 协作、任务规划与过程可控性、推理效率、意图理解、Computer Use、Browser Use、联网搜索与知识应用、轨迹数据反馈与自我改进、Session 查看切换与恢复。 |
| 资源与并发稳定性（2 项） | 资源占用、多路并发稳定性。 |

每项均附具体观察提示。填写时注意：

- **Context 压缩与记忆**：前者关注当前窗口压缩后的目标、约束、决定和待办是否保留；后者关注背景和经验的持久复用。
- **自动纠错与轨迹改进**：前者关注本次错误能否自动处理并验证；后者需要说明后续任务是否减少同类错误，以及改进是自动完成还是人工整理后实现。一次重试成功不足以说明持续改进。
- **长程连续性与 Session**：前者关注一个任务的持续推进；后者关注历史查看、任务辨认、会话切换与恢复是否流畅。
- **Computer Use、Browser Use 与联网搜索**：分别关注桌面操作、浏览器交互、资料查找及正确应用，不预设工具一定支持这些能力。
- **交付质量**：说明 Spec 与代码是否一致，以及编译、运行、测试的实际结果；未执行的检查要注明。
- **资源与并发**：无需专业监控，可写真实卡顿感受；有数据时补充空闲和峰值内存（MiB / GiB）、CPU（%）及结束后是否释放。共享服务注明整体观测值。并发稳定性结合记录的并发数量评价，只体验单路时留空。

## 评分口径

| 分数 | 参考含义 |
| --- | --- |
| 1 很差 | 明显不满足需要，严重影响任务。 |
| 2 较差 | 帮助有限、问题频繁，需要较多干预。 |
| 3 一般 | 基本可用，仍有明显不足。 |
| 4 较好 | 表现良好，仅有少量问题。 |
| 5 很好 | 充分满足本次场景需要，表现稳定顺畅。 |

高分统一表示更好：上手越容易、资源影响越小，评分越高。最有价值的特性按实际帮助程度评分，资源项结合占用是否合理及对使用的影响评分。

未体验或不适用时评分留空，在说明中写明本次不需要、未配置、环境受限或无法确认支持情况等原因。实际尝试失败可以按真实体验评分。未知不计零分。

评分单元格限制为 1～5 的整数或空白。工具表头与评价项列已冻结，说明区支持自动换行；文字较多时可调整行高。

模板不包含需求号、预填体验结论、总分、权重或排名。模型与环境、实际过程、具体经历和分数需结合阅读。
