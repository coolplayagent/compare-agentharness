# 四种研发 Agent 工具试点评测

[下载 Excel 模板](outputs/01a0e736/AI研发Agent四工具试点评测模板.xlsx)

用于研发试点团队在同一批特性上比较 **Claude Code、Codex、Trae、CodeArts** 的实际交付结果与使用体验。模板不预填工具成绩，不预设优劣。工具的具体产品、版本、模型、套餐和权限配置由试点团队登记。

## 开始填写

1. 在 **试点设置** 中登记项目、基准提交、环境、提示词和四种工具的配置，约定评测路径、费用口径与评分权重。
2. 在 **特性清单** 中填写相同的业务需求、验收集、质量门槛与时间上限，每个特性安排 1–3 轮。
3. 各工具从相同干净提交独立开发。在 **运行记录** 中分别记录 AI 原始产物、人工修正后的验收结果、投入时间、干预与费用，附证据包并由复核人核验。
4. 对照 **评分与指南** 的行为锚点填写 **能力评分**，用 **过程与问题** 留存关键事件和复验动作。
5. 查看 **配对比较** 和 **对比总览**，填写能力差距、适用场景与下一步结论。

黄色单元格为填写项，灰蓝色单元格为公式或固定标识。支持表头筛选与冻结窗格。填写时保留运行 ID、配对 ID 和特性 ID，不覆盖公式。

## 比较口径

- **客观结果**：达标交付率、AI 原始与最终验收通过率、净耗时、人工投入、人工改码、干预次数、故障与超时、工具费用。
- **能力体验**：需求理解、仓库上下文、方案与实现、代码可维护性、测试与修复、自主执行、交互可控性、工程融入。采用 1–5 分行为锚点，权重可在正式评测前调整，合计须为 100%。
- **统一配对**：同一特性、同一轮次四种工具的记录均齐备才纳入主表。评分与费用分别采用四工具均齐备的配对子集，并显示各自样本数。
- **保留失败**：超时、工具故障和主动终止均应记录；完整且条件一致的失败记录进入达标率分母。不能仅保留最好的一次。
- **区分缺失和零**：缺评分不当作 0；未知费用留空，确认无支出填 0。未观察到的维度留空，客观记录仍可比较。
- **解释边界**：结论针对实际工具、模型、配置和操作者组合。均值按每次运行等权计算。先看交付率再解读耗时，避免将提前失败误认为更高效率。

默认预留 **12 个特性 × 3 轮 × 4 工具 = 144 次运行**。每项可减少轮次；空白特性名称代表未启用。超过容量、改变工具配置或切换“受控基线 / 最佳实践”时，请新建批次文件。不要直接向表尾追加记录后使用原有汇总范围。

建议通过独立分支、新会话、人员与工具轮换、统一验收以及保留会话和提交证据控制偏差。小样本应结合逐组差异与失败事件解释，不把平均体验分当作统计显著的工具排名。

## 验证范围

模板已通过 11 项配对与边界场景检查，覆盖空白、完整配对、失败与零值、缺评分、缺费用、条件偏差、非法通过数、重复 ID、权重错误、超预算及最后一条预留记录，并完成各工作表版式检查与 LibreOffice 复算。已核对导出文件的筛选、冻结窗格和输入校验；未在 Microsoft Excel 客户端实测。

验证使用合成数据，正式模板保持空白，不包含任何真实工具测评结论。
